Struttura del Sottoalbero del Progetto
Kalabria Coast to Coast

Questa relazione mappa in modo dettagliato l'intero sottoalbero (struttura delle directory) dell'applicazione web Kalabria Coast to Coast sviluppata in Laravel. Per facilitare la comprensione in sede di esame, è stata fatta una distinzione visiva fondamentale: le directory evidenziate rappresentano il codice sorgente scritto da noi (logica di business, interfacce, rotte, database), distinguendole nettamente dalle directory gestite automaticamente dal framework e dai pacchetti esterni.

Dettaglio delle Directory di Progetto Codice del Progetto

📁 app/ 100% Nostro

È il cervello dell'applicazione. Qui abbiamo scritto tutta la logica che fa funzionare Kalabria Coast to Coast.

  • Http/Controllers/: Contiene i "direttori d'orchestra". Abbiamo creato ad esempio OutingController per salvare e rifiutare uscite, e ParticipationController per gestire le iscrizioni.
  • Models/: Contiene le classi che dialogano col database usando Eloquent ORM. Abbiamo creato i modelli User, Outing, ParticipationRequest e DigitalCredential, definendo le loro relazioni esatte (es. $outing->participationRequests()).
📁 resources/views/ 100% Nostro

Qui risiede l'intera interfaccia grafica sviluppata su misura per l'utente, utilizzando HTML, Bootstrap 5 e la sintassi Blade di Laravel.

  • Sottocartelle principali: admin/ (gestione uscite e guide), outings/ (catalogo uscite pubbliche, pulsanti di iscrizione), profile/ (dashboard utente, storico partecipazioni e gamification dei trofei).
📁 database/ 100% Nostro

Non contiene il database fisico, ma le "istruzioni" per costruirlo in modo programmatico.

  • migrations/: Contiene i file creati da noi per costruire tabelle e colonne. Grazie a questi file, l'intero database può essere generato da zero su qualsiasi PC con un solo comando.
  • seeders/: Script scritti da noi per inserire utenti fittizi, le guide ufficiali e i dati di prova (come l'utente mario@example.com) per testare l'app.
📁 routes/ 100% Nostro

Il centralino dell'applicazione. Nel file web.php abbiamo definito a mano ogni singolo URL visitabile dagli utenti e specificato quali rotte sono protette (visibili solo all'admin o solo agli utenti loggati tramite middleware).

Dettaglio delle Directory di Supporto Codice del Framework

📁 vendor/ e node_modules/ Intoccabili

Contengono rispettivamente tutto il codice PHP di Laravel (gestito tramite Composer) e le librerie Javascript (gestite tramite NPM). Qualsiasi modifica manuale in queste directory andrebbe persa al primo aggiornamento software. Sono il "motore" nascosto che esegue il nostro codice.

📁 storage/ e bootstrap/cache/ Generati dal server

Cartelle dinamiche usate dal server per salvare file temporanei, compilare le viste Blade in PHP nativo (per massimizzare la velocità) e conservare i log di sistema in caso di errori (es. storage/logs/laravel.log). Anche queste directory non devono essere manipolate direttamente dallo sviluppatore.
